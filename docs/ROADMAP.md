# FMIndex 개발 로드맵

## 운영 원칙

각 Phase는 코드량이 아니라 **승인 기준(exit gate)** 충족 여부로 종료한다. 다음 Phase로 넘어가기 전에 데이터·오류·검증 증거를 저장한다.

---

## Phase 0 — 기반 계약과 데이터 접근성 검증

### 목표

실제 대량 수집 전에 데이터 구조, 접근 실패 양상, 저장 계약, 운영 중단 기준을 확정한다.

### 작업

- 공통 TypeScript·Zod 스키마 정의
- 게시글·댓글·분석·지수 이벤트 계약
- 로컬 SQLite 스키마 초안
- 목록·본문·댓글 HTML fixture 수집 절차
- fixture 기반 파서
- 게시물 ID·작성시각·조회·추천·댓글 수 정규화
- 중복·수정·삭제 상태 모델
- dry-run collector
- 요청 제한·백오프·429 중단 상태
- 데이터 보존 worker 설계

### 종료 기준

- fixture 테스트가 안정적으로 통과한다.
- 신규·중복·수정 상태를 재현할 수 있다.
- 시간대와 날짜 파싱 규칙이 문서화돼 있다.
- 요청을 보내지 않고도 collector 흐름을 테스트할 수 있다.
- 429와 정책 변경 시 자동 중단 상태가 구현돼 있다.
- 원문 만료 시나리오가 테스트 가능하다.

### 결과물

```text
packages/contracts
packages/source-adapters
apps/collector dry-run
SQLite migration 001
fixture test suite
Phase 0 evidence report
```

## Phase 1 — 제한적 증분 수집 MVP

### 목표

낮은 요청량으로 신규 게시물을 식별하고 선택적 본문 수집이 가능한지 확인한다.

### 작업

- 목록 페이지 일정 주기 관찰
- 체크포인트와 마지막 성공 ID 저장
- 요청 간 랜덤 지연
- 본문 선택 기준
- 제한적 댓글 수집 기준
- 429·5xx·타임아웃 처리
- 누락·중복·파싱 실패 통계
- 원문 7일 만료

### 종료 기준

- 연속 실행 후 중복 저장이 통제된다.
- 수집 성공률과 누락 추정치를 계산할 수 있다.
- 장애 후 체크포인트에서 재시작한다.
- 429 발생 시 즉시 멈추며 자동 우회를 하지 않는다.
- 원문 만료가 실제로 동작한다.

### 금지

- 요청 주기 최적화 명목의 공격적 부하 증가
- 프록시 회전
- CAPTCHA 또는 로그인 우회
- 여러 데이터 원천 동시 추가

## Phase 2 — 분석 스키마와 사람 기준 데이터

### 목표

한국 주식 커뮤니티의 방향성·감정·행동 의도·반어를 구조화하고 평가 가능한 기준 데이터를 만든다.

### 작업

- 종목명·코드·별칭 사전
- 시장·업종·거시 대상 분류
- 주식 은어·밈 사전
- 라벨링 도구 또는 최소 검수 화면
- 1,000개 이상 사람 라벨 표본
- 20% 이상 이중 라벨링
- 불일치 해결 기록
- 분석 JSON Schema v1

### 종료 기준

- 라벨 가이드 버전이 고정된다.
- 클래스 분포와 어려운 사례 비율을 확인한다.
- 학습·개발·평가 데이터의 중복이 제거된다.
- 반어·댓글·복수 대상 사례가 평가 세트에 포함된다.

---

## Phase 3 — 로컬 LLM 분석 MVP

### 목표

교체 가능한 로컬 모델을 통해 구조화된 분석 결과를 생성하고 사람 라벨과 비교한다.

### 작업

- OpenAI 호환 모델 공급자 인터페이스
- 규칙 기반 전처리
- 명확한 사례의 비LLM 처리
- 애매한 사례의 LLM 분석
- JSON Schema 검증
- 한 번의 교정 재시도
- 실패 quarantine
- 모델·프롬프트·설정 버전 기록
- 평가 리포트

### 잠정 종료 기준

- 관련성 정확도 90% 이상
- 방향성 Macro F1 0.80 이상
- 대상 인식 정확도 90% 이상
- 행동 의도 Macro F1 0.70 이상
- 구조화 출력 성공률 99.5% 이상
- 동일 입력 재실행 일치율 99% 이상

기준 미달 시 더 큰 모델로 무조건 교체하지 않고 오류 유형부터 분해한다.

## Phase 4 — 지수 엔진 MVP

### 목표

15분 단위로 설명 가능하고 재현 가능한 시장심리지수를 만든다.

### 작업

- 시간 감쇠
- 참여도 로그 변환과 상한
- 한 게시물·한 작성자의 최대 영향 제한
- 중복·도배 감점
- 시장심리·공포탐욕·관심도·분열도 계산
- 15분·1시간 변화속도
- 유효 표본 수와 데이터 신선도
- 산식 버전별 재계산

### 종료 기준

- 같은 입력·산식 버전으로 같은 결과가 나온다.
- 극단값의 주요 기여 레코드를 추적할 수 있다.
- 표본 부족 시 `INSUFFICIENT_DATA`가 표시된다.
- 수집 지연 시 정상 지수로 위장하지 않는다.
- 지수 산식 변경 전후를 비교할 수 있다.

---

## Phase 5 — 시장 데이터 결합과 연구 검증

### 목표

승인된 시장 데이터 공급자를 연결해 심리와 가격·거래량의 동행·괴리를 분석한다.

### 작업

- 시장 데이터 공급자와 라이선스 검토
- KOSPI·KOSDAQ·주요 지수 시간 정렬
- 관심 급증 종목 가격·거래량 연결
- 동시간·5분·15분·30분·60분 이후 구간 비교
- 미래 데이터 누출 방지
- 상승·하락·횡보장 구간 분리
- 사건·시간대별 연구 리포트

### 종료 기준

- 데이터 시각과 거래일 정렬이 검증된다.
- 백테스트에 미래 데이터가 섞이지 않는다.
- 결과가 없는 경우에도 그대로 보고한다.
- 상관관계를 수익 보장이나 인과관계로 표현하지 않는다.

---

## Phase 6 — 내부 운영 콘솔

### 목표

공개 화면보다 먼저 수집·분석·지수 상태를 운영자가 확인하게 한다.

### 화면

- 마지막 성공 시각
- 요청 수·실패 수·429 수
- 신규·중복·수정·삭제 건수
- 분석 backlog와 실패 quarantine
- 낮은 확신도 검수 큐
- 시간창별 표본 수
- 상위 지수 기여 레코드
- 모델·프롬프트·산식 버전
- 원문 만료 상태와 디스크 사용량

### 종료 기준

- 장애를 로그 파일을 직접 열지 않고 파악할 수 있다.
- 지수 값의 생성 근거를 추적할 수 있다.
- 재처리·재집계 요청이 감사 로그에 남는다.

---

## Phase 7 — 공개 대시보드 MVP

### 목표

원문을 재배포하지 않으면서 현재 커뮤니티 시장심리를 설명한다.

### 공개 기능

- 현재 펨코지수
- 15분·1시간 변화
- 장중 차트
- 공포·탐욕
- 관심도
- 의견분열
- 관심 급증 시장·업종·종목
- 시장가격과의 괴리
- 유효 표본 수와 데이터 신선도
- 방법론·한계·면책

### 종료 기준

- 원문 전체와 작성자 정보가 노출되지 않는다.
- 데이터 지연·표본 부족이 명시된다.
- 모바일·데스크톱에서 핵심 지표를 이해할 수 있다.
- 지수 변화의 요인을 자체 요약으로 설명한다.
- 공개 전 데이터 원천·저작권·개인정보·시장 데이터 라이선스를 재검토한다.

## Phase 8 — 자동 리서치 콘텐츠

### 목표

1번 사업모델인 자동 주식 콘텐츠를 독점 파생 데이터의 유통 채널로 연결한다.

### 콘텐츠 유형

- 장전 시장심리 브리핑
- 장중 심리 급변 보고서
- 장 마감 심리 요약
- 주간 공포·탐욕 변화
- 가격과 심리가 엇갈린 종목 분석

모든 콘텐츠는 사건 또는 지수 변화가 있을 때만 생성한다. 종목마다 의미 없는 글을 대량 발행하지 않는다.

## Phase 9 — 다중 플랫폼 확장

### 전제

FMKorea 단일 원천에서 수집·분석·운영·정책 검증이 끝난 뒤 진행한다.

### 후보

- 네이버 종목토론방
- 토스증권 커뮤니티
- 기타 공개 투자 커뮤니티

### 신규 지수

- 플랫폼별 심리지수
- 통합 개인투자자 심리지수
- 플랫폼 간 심리괴리지수
- 반응속도 차이

각 데이터 원천은 독립된 정책·어댑터·보존 범위를 가져야 한다.

## 첫 구현 작업 권장 범위

첫 코드 PR은 다음만 포함한다.

```text
agent/phase-0-contracts-fixtures

- packages/contracts 초기화
- source post/comment/analysis/index Zod schema
- fixture 디렉터리와 비민감 샘플
- fixture loader
- schema unit tests
- SQLite migration 초안
- README 실행 명령 갱신
```

실제 네트워크 요청 코드는 첫 구현 PR에 포함하지 않는다.
