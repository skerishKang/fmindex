# FMIndex 데이터 정책

## 1. 목적

FMIndex는 공개 게시판의 원문을 장기 복제·재배포하는 서비스가 아니라, 제한된 수집을 통해 시장심리의 파생 데이터를 생성하는 연구 플랫폼이다. 이 문서는 수집, 저장, 이용, 공개, 만료, 삭제의 기준을 정한다.

## 2. 데이터 분류

### A. 출처 메타데이터

- 데이터 원천 ID
- 게시물 ID
- URL
- 작성시각
- 최초·최종 관찰시각
- 조회·추천·댓글 수
- 수집 상태와 HTTP 상태

장기 보존 가능하되 외부 공개 범위는 최소화한다.

### B. 원문 데이터

- 제목
- 본문
- 댓글
- 원본 HTML 또는 응답 일부

분석·파싱 검증에 필요한 제한된 기간만 보관한다. 기본 보존기간은 7일이다.

### C. 정규화 데이터

- 정제 텍스트
- 문서 유형
- 시장·업종·종목 후보
- 콘텐츠 해시
- 수정·삭제 상태
- 비식별 작성자 해시

모델 재분석과 품질 검증 목적에 필요한 범위만 보존한다.

### D. 파생 분석 데이터

- 시장 관련성
- 방향성
- 감정
- 행동 의도
- 시간 범위
- 반어 가능성
- 분석 확신도
- 모델·프롬프트·스키마 버전

FMIndex의 핵심 장기 자산이다.

### E. 집계 데이터

- 시간창별 지수
- 표본 수
- 데이터 신선도
- 관심도·분열도·변화속도
- 시장 데이터와의 괴리
- 산식 버전

외부 공개와 장기 연구에 사용하는 기본 데이터다.

### F. 사람 라벨 데이터

- 라벨러 ID 또는 비식별 코드
- 라벨 결과
- 판단 근거
- 불일치 해결 결과

모델 평가와 기준 개선을 위해 장기 보존할 수 있다. 원문 포함 범위는 최소화한다.

## 3. 수집 원칙

- 서비스 정책과 접근 범위를 검토한다.
- 목록 페이지를 우선 관찰하고 본문·댓글은 선별 수집한다.
- 요청 동시성과 빈도를 낮게 유지한다.
- 인증, CAPTCHA, 접근 제한을 우회하지 않는다.
- 429가 발생하면 즉시 중단한다.
- 필요하지 않은 프로필·개인정보·첨부파일을 수집하지 않는다.
- 수집 목적과 무관한 게시판·카테고리로 범위를 확대하지 않는다.

## 4. 식별정보 처리

작성자 닉네임은 공개 화면에 표시하지 않는다. 내부에서 중복·도배 방지에 작성자 단위 정보가 필요하면 다음 방식으로 처리한다.

```text
author_hash = HMAC-SHA256(source_id + normalized_author_id, local_secret)
```

- 단순 SHA-256 대신 로컬 비밀키를 사용하는 HMAC을 권장한다.
- 비밀키는 `.env` 또는 별도 비밀 저장소에 두며 Git에 저장하지 않는다.
- 원래 닉네임으로 역변환할 수 있는 매핑 테이블을 만들지 않는다.
- 작성자별 장기 프로파일을 외부에 제공하지 않는다.

원문에 이메일, 전화번호, 계좌번호 등 직접 식별정보가 포함된 경우 정규화 단계에서 마스킹하고 분석 입력에서도 제거한다.

## 5. 보존기간

초기 기본값:

| 데이터 | 기본 보존 | 비고 |
|---|---:|---|
| 원본 HTML·원문 | 7일 | 파싱·분석 검증 후 만료 |
| quarantine 원문 | 14일 | 오류 해결 후 즉시 삭제 가능 |
| 정규화 텍스트 | 30일 | 재분석 필요성에 따라 단축 |
| 출처 메타데이터·해시 | 장기 | 원문 재배포 불가 |
| 파생 분석 데이터 | 장기 | 모델 버전 포함 |
| 집계 지수 | 장기 | 공개·연구용 |
| 사람 라벨 데이터 | 장기 | 최소 원문·접근 통제 |
| 운영 로그 | 30일 | 원문 전체 기록 금지 |

보존기간을 늘리려면 목적, 필요성, 위험, 삭제 계획을 PR과 결정기록에 남긴다.

## 6. 삭제와 만료

Retention Worker는 최소 다음을 수행한다.

1. `expires_at`이 지난 원문을 탐색한다.
2. 파생 데이터와 콘텐츠 해시가 존재하는지 확인한다.
3. 삭제 대상 수와 용량을 실행 로그에 기록한다.
4. 원문·HTML을 삭제한다.
5. 삭제 성공·실패를 감사 로그에 남긴다.
6. 실패 항목은 무한 재시도하지 않고 운영 큐로 보낸다.

게시물이 원 데이터원에서 삭제된 것이 감지되면 상태를 `SOURCE_DELETED`로 기록하고, 보존 필요성이 없는 원문은 조기 삭제한다.

## 7. 외부 공개 기준

공개 가능:

- 시간대별 집계 지수
- 표본 수와 데이터 신선도
- 비식별 주제·시장·업종·종목 통계
- 지수 산식과 방법론
- 짧은 자체 요약
- 원 출처로 연결되는 제한적 링크

기본적으로 공개하지 않음:

- 원문 전체
- 댓글 전체
- 작성자 닉네임 또는 작성자 해시
- 작성자별 평가·행동 이력
- 내부 수집 헤더·쿠키·세션 정보
- 로컬 LLM 입력 원문 덤프
- 원문 검색 API

짧은 인용이 필요한 경우에도 목적상 필요한 최소 범위로 제한하고, 출처 링크와 게시 시각을 함께 제공한다.

## 8. 연구·개발용 내보내기

데이터셋을 내보낼 때 다음을 포함한다.

- export ID
- 생성자
- 생성시각
- 목적
- 포함 필드
- 레코드 수
- 원문 포함 여부
- 만료일
- 저장 위치
- 삭제 확인일

개발자 간 전달은 원문 전체가 아니라 fixture 또는 최소 샘플을 우선 사용한다.

## 9. 접근 통제

- Raw 데이터: 수집·품질 담당자만 접근
- Normalized 데이터: 분석 개발자와 검수자 접근
- Analysis·Aggregate: 제품 개발자 접근
- 공개 API: 승인된 집계 필드만 접근
- 비밀키·세션·쿠키: 운영 환경에서만 접근

로컬 개발에서도 공유 PC나 동기화 폴더에 원문·비밀키를 두지 않는다.

## 10. 데이터 품질과 권리 검토

외부 공개 또는 유료화 전에는 다음을 재검토한다.

- 데이터 원천 이용정책
- 저작권과 데이터베이스 권리
- 개인정보 및 재식별 위험
- 인용 범위
- 시장 데이터 라이선스
- 유료 제공 시 투자자문 관련 규제 가능성

기술적으로 수집 가능하다는 사실을 상업적 이용 권한으로 간주하지 않는다.

## 11. 위반 또는 사고 대응

다음 상황이 발생하면 신규 수집과 외부 공개를 중단한다.

- 비밀키·세션 유출
- 원문 또는 작성자 정보의 의도치 않은 공개
- 보존기간 경과 데이터가 삭제되지 않음
- 데이터 원천의 중단·삭제 요청
- 정책 또는 접근 방식의 중대한 변경
- 내부 데이터셋의 무단 외부 반출

사고 기록에는 발생시각, 영향 범위, 노출 데이터, 즉시 조치, 삭제·회수 결과, 재발 방지 변경을 포함한다.
